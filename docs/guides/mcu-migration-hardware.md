# 浮动床热风烘焙机：MCU 选型与分阶段迁移建议

日期：2026-11-10。本文是结合当前源码、用户确认的硬件和厂商资料形成的设计建议；尚未实现 MCU 固件、绘制电路图或进行实机验收。具体管脚和元件参数应在接口核实后确定。

## 1. 已确认的设备与推荐结论

| 项目 | 用户确认的现状 | 对设计的影响 |
| --- | --- | --- |
| 机型 | 浮动床式、纯热风 | 送风同时决定流化和传热；没有滚筒电机需求 |
| 加热 | 220 VAC、1600 W；已有外接供电、台泉温控器和可控硅 | 先保留现有功率部分；额定电流初算约 7.3 A，不代表器件选型或散热结论 |
| SSR | SSR-25DA，铭牌输入 3–32 VDC、输出 24–480 VAC | 制造商、输入电流、零交越特性和现有连接关系仍待核对，不能仅凭名称认定 |
| 风机 | 18 VDC、150 W 无刷风机，已有供电和旋钮，用户确认 PWM 调速 | 先复用现有驱动；额定输入电流初算约 8.3 A，不应经过逻辑板供电支路 |
| 风机旋钮 | 三根线 | 仍需核对线序、参考地、PWM 电平/频率及控制端定义；三线旋钮本身也可能是电位器，不能直接按 MCU PWM 引脚接线 |
| 温度 | 一路 K 型热电偶，在豆层、出风口上方一点 | 在本项目中作为豆层测点记录；该测点不能同时提供独立进风温度或风量证明 |
| 上位机 | 手机、电脑；目前保留树莓派测试，后续希望更小、更便宜 | 设备协议与具体上位机分离，树莓派最终成为可选设备 |

**首选 ESP32-S3 单芯片控制通信板。第一阶段用它做 TC4S 的无线/USB 通信入口，第二阶段再接管本地温控。** 对一路温度、一路 SSR、一路已有驱动的风机，这个选择兼顾体积、开发工作量和成本；当前需求不需要默认增加第二颗主控。

建议自画板从 **ESP32-S3-WROOM-1-N8** 或金属机壳适用的外接天线版本 **ESP32-S3-WROOM-1U-N8** 起步，使用 ESP-IDF / C/C++。模组自带射频相关电路，首板沿用厂商布局要求。外置天线应安排在适合辐射的位置，而非留在封闭金属柜内。[S3 模组手册](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)

## 2. 方案比较与具体器件

| 方案 | 能力与取舍 | 本设备建议 |
| --- | --- | --- |
| ESP32-S3 | 双核最高 240 MHz，2.4 GHz Wi-Fi、BLE 5，USB、PWM、捕获等外设 | 主推；无线和本地控制一起实现，需验证网络压力下的控制延迟 |
| STM32G431RBT6 + ESP32-C3 | STM32 M4F 170 MHz、128 KB Flash、32 KB SRAM；ESP 负责网络 | 想采用熟悉的 STM32 工具链或分离控制/无线时可选，须控制固件体积 |
| STM32G474RET6 + ESP32-C3 | M4F 170 MHz、512 KB Flash、128 KB 总 SRAM、LQFP64，控制外设余量较大 | 后续多传感器、复杂驱动时的扩展路线；当前机型可先用单 S3 |
| Raspberry Pi Pico 2 W | RP2350 微控制器板，双核 150 MHz、520 KB SRAM、板载无线 | 技术上可用；它属于 MCU 板，与运行 Linux 的树莓派不同，当前转换生态的收益有限 |
| 运行 Linux 的树莓派 | 可以继续运行现有 Python 服务、网页、记录与 AI 宿主 | 保留为测试/日志/显示上位机，逐步解除它对控制周期的影响 |

芯片事实见 [S3](https://www.espressif.com/en/products/socs/esp32-s3)、[G431](https://www.st.com/en/microcontrollers-microprocessors/stm32g431rb.html)、[G474](https://www.st.com/en/microcontrollers-microprocessors/stm32g474re.html)、[Pico 2 / 2 W 官方规格](https://www.raspberrypi.com/products/raspberry-pi-pico-2/)。表中的适用性是本项目的工程判断。

S3 模组选择：

- N8 提供 8 MB Flash；当前设备不依赖大容量 PSRAM。完整网页、曲线库和 AI 不必全部搬进 MCU，最终 RAM 余量要按 Wi-Fi、BLE、TLS 和缓存的实际组合验证。
- N8R8 / N16R8 适合开发时需要较大缓存的场景，但 R8 常规配置的模组环境温度上限为 65°C。厂商对 PSRAM ECC 条件另有说明，不能把所有后缀一概视为 85°C；正式设计按具体订货型号核对。
- R8 模组 GPIO35/36/37 受 PSRAM 占用约束；USB 使用 GPIO19/20，GPIO0/3/45/46 涉及启动配置。先确定后缀，再分配引脚。[S3 模组手册](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)
- 若后续使用 STM32 + 无线协处理器，优先评估 **ESP32-C3-MINI-1-N4X / MINI-1U-N4X**。当前官方手册把这些 X 版本列为 Recommended，老 N4/H4 列为 NRND。C3 MINI-1 约 13.2 × 16.6 mm，适合作为小型无线接口。[C3 MINI 官方手册](https://documentation.espressif.com/esp32-c3-mini-1_datasheet_en.html)

ESP32-C6 的 Wi-Fi 6 / 802.15.4 不是本机现有需求；ESP32-P4 本体无 Wi-Fi/BLE。H7 的较强算力也不会直接改善本机这一路测温的质量，暂不作为首选。[C6](https://documentation.espressif.com/esp32-c6_datasheet_en.html)、[P4](https://docs.espressif.com/projects/esp-idf/en/stable/esp32p4/get-started/index.html)、[H743/753](https://www.st.com/en/microcontrollers-microprocessors/stm32h743-753.html)

## 3. 现有软件的实际迁移边界

当前不是把一套现成的 MCU 功率控制代码换个平台：

- `roaster/src/hardware/tc4s_async.py` 通过 Modbus RTU 读取 PV `0x0000`、SV `0x0002`，写入 SV；默认 9600、8N1、站号 1。现有遥测没有实测加热功率、风量或风机转速。
- `roaster/src/core/roaster_controller.py` 在 Python 中执行曲线插值、前看、RoR、事件和烘焙状态机，向 TC4S 下发目标温度。配置虽有 `pid` 参数，当前控制器并没有把温差换算为 SSR 占空比的功率 PID 实现。
- 配置中的 0.5 秒轮询还包含通信与重试耗时，不是硬实时周期。当前温度读取/目标写入按整数处理；新协议需要明确温度单位和分辨率。
- 现有 FastAPI、桌面 Tauri、完整工作台服务、记录库与 AI 宿主继续放在电脑或可选的树莓派；手机运行网页或另行开发的原生客户端。MCU 固件需重写对应执行部分，不能直接安装现有 Python/Tauri 程序。
- 当前软件异常/停止主要尝试写 SV=0；通信已经断开时，这个命令可能到不了 TC4S。它不等于独立断开加热电源。

具体当前连接方法见 [真实设备连接与调试](real-device-setup.md)。源码与模拟验证不代表真实树莓派、TC4S、加热和急停已经接机验收。

## 4. 分三阶段落地，保留树莓派测试

### 阶段 A：通信板接入，沿用 TC4S 与现有风机旋钮

```text
手机 / 电脑 / 可选树莓派
      │ Wi-Fi 或 USB
      ▼
ESP32-S3 ── 隔离 RS485 ── TC4S ── 现有加热执行部分
                               │
                           原 K 型探头
风机仍由现有驱动器和旋钮控制
```

先实现有效 PV/SV 遥测、连接状态、显式命令确认与上位机适配。TC4S 继续承担现有测温与温控，具体输出方式按其型号核实。MCU 作为 RS485 唯一主站；电脑和树莓派改为访问 MCU，不再同时在同一总线上轮询 TC4S。

这个阶段仅让通信入口独立，曲线执行如仍在 Python 中，就尚未达到脱离上位机独立烘焙的目标。应验证主机/网络丢失的行为；无线桥掉线不能被误认为 TC4S 已自动停热。

### 阶段 B：板上执行完整曲线与本地保护

```text
手机 / 电脑 / 可选树莓派
      │ 已校验曲线、显式操作、实时遥测
      ▼
ESP32-S3：本地时钟、状态机、曲线、闭环、故障记录
   ├─ SPI ── K 型热电偶前端 ── 豆层探头
   ├─ 驱动级 ── SSR 低压控制端
   ├─ 经适配的 PWM / 控制接口 ── 原无刷风机驱动器
   └─ 风量、超温、急停与加热许可反馈

独立超温 / 急停 / 失风保护 ── 独立撤销加热供电许可
```

先只读比对和接低压测试负载，再迁移闭环。直接 SSR 控制需要新实现和整定 PID，包括输出限幅、抗积分饱和、传感器失效与风量变化时的行为。

同一支 K 型探头不要无源 Y 分接到 TC4S 和新采集芯片。过渡期直接读 TC4S，迁移时整路切换；若需同时比对，使用独立测试探头或适合的双元件探头。

### 阶段 C：树莓派成为选配

手机/电脑通过 Wi-Fi 监视和交互；电脑通过 USB 调试。曲线在开始前完整上传、校验，再由用户显式 START。MCU 使用本地单调时钟执行，不靠上位机持续按时发包。树莓派继续可以做屏幕、调试、记录与网关，移除它不应改变设备控制时序。

断网首版建议进入撤热与已验证的冷却流程；若未来支持断网续烘，需要另行验证完整曲线、本地联锁和操作者停止手段，不能默认无限维持最后加热输出。设备复位或重连不自动开始、不自动续烘。

## 5. 配套电路与模块建议

| 功能 | 首版建议 | 边界 |
| --- | --- | --- |
| 处理与无线 | ESP32-S3-WROOM-1/1U-N8 | 首板用模组，按天线净空、启动与供电要求布板 |
| TC4S 接口 | ISO1410 类隔离 RS485 + 隔离 DC/DC，或完整隔离模块 | 3.3 V 逻辑；ISO1410 本身不包含隔离供电，偏置与终端按拓扑配置 |
| 一路 K 型采集 | MAX31856，SPI，首版留 1 路并可选第 2 路扩展 | 含冷端补偿、断线检测和 50/60 Hz 抑制；需先核对探头绝缘/接地形式 |
| SSR 控制 | 晶体管/MOSFET 低压缓冲驱动，硬件默认关断 | 3–32 V 标注不代表 3.3 V GPIO 有足够驱动裕量；先核实输入电流 |
| 风机控制 | 保留现有驱动器；预留 PWM、参考地和可选隔离/电平适配 | 待核实控制端的真实电平、频率、极性、断线/复位行为后再接 |
| 模拟调速扩展 | 若实际需要电压控制，可预留 MCP4728 等 I²C DAC + 缓冲/放大 | S3 无片上通用 DAC；0–10 V 需要相应供电和输出电路，不能直接靠 3.3 V 引脚 |
| 送风证明 | 优先留失风/风量开关输入，也可留差压传感器 I²C/模拟接口 | 量程、取压点、防尘与阈值按风道验证；转速不能单独证明风量 |
| 逻辑供电 | 独立合适的 5 V 电源，或从符合条件的 18 V 电源经 Buck 降压，再生成 3.3 V | LMR33620 类器件可评估；需核算启动/瞬态、噪声、散热和电机回流 |
| 电压监控/看门狗 | 可预留 TPS3850 类器件与硬件加热许可门控 | 看门狗健康信号应来自有效控制任务，不由单独常跑的通信定时器代喂 |
| 本地操作 | 实体停止、状态灯、蜂鸣器、可选启动/确认 | 物理停止和保护链独立于手机页面 |

资料：[ISO1410](https://www.ti.com/product/ISO1410)、[隔离信号与电源设计](https://www.ti.com/document-viewer/lit/html/SLLA416)、[MAX31856](https://www.analog.com/en/products/max31856.html)、[MCP4728](https://www.microchip.com/en-us/product/MCP4728)、[LMR33620](https://www.ti.com/product/LMR33620)、[TPS3850](https://www.ti.com/product/TPS3850)。这些是候选电路类别，不是已经核定、可直接生产的 BOM。

### 测温与布板

豆层探头可以作为当前 BT 测点标签，但出风口附近读数会受热风与探头响应影响，不代表已经校验的豆内温度；不要在界面上同时生成一个不存在的 ET。若后续发现热风温度变化过快或希望独立限制进风温度，可增加第二支实际探头；独立超温保护也不能仅依赖这支控制探头和同一 MCU。

MAX31856 不直接适用于所有接地型探头。先核实热端与护套/机壳是否导通；金属护套本身不证明热端接地。若需要接地探头，选择经验证的隔离采集或其他合适前端，不能把 ±45 V 输入保护当隔离。[ADI 接地型热电偶说明](https://ez.analog.com/data_converters/a/documents/c/max31856-faq/DO12495/is-it-possible-to-use-maxim-s-thermocouple-to-digital-converter-with-grounded-thermocouple)

热电偶接入端与 MAX31856 尽量处于同一温度区域，远离 Buck、电机功率线、ESP 发热区与 SSR 散热器。数字分辨率不等于探头或整机精度，校验要包括冷端误差、探头、接线与电磁干扰。[ADI 冷端布局说明](https://ez.analog.com/data_converters/a/documents/c/max31856-faq/DO12492/where-is-the-optimal-position-to-place-the-max31856-for-accurate-cold-junction-compensation)

若未来改 PT100/PT1000，选 MAX31865 等 RTD 前端；多路自研可评估 ADS124S08，但它的 12 个复用模拟输入不等于 12 路同时采样的独立差分热电偶通道，仍需冷端、保护和切换稳定时间设计。[MAX31865](https://www.analog.com/en/products/max31865.html)、[ADS124S08](https://www.ti.com/product/ADS124S08)

### 加热与送风

先厘清“可控硅”和“SSR”是否为同一件设备，不先假设还有一个独立调功器。若 SSR 确认为零交越型，按其规格使用工频整周波/时间比例调功，窗口经热风机实际响应整定；不能用 kHz PWM 获得线性交流调压。相位调功属于另一套器件及同步设计。[OMRON 控制方式说明](https://www.ia.omron.com/support/guide/18/overview.html)

保持已有 18 V 风机供电与驱动，调速优先从驱动控制端接入，不默认对风机电源做斩波。需核实三线旋钮究竟是电位器输入还是可外接 PWM 的信号端；用户确认 PWM 控速并不能确定该三线端子的电气定义。

浮动床应先证明送风再允许加热，失风撤热。风机在热故障后是否继续、以何速度冷却，按风道、机械防护和电源条件验证，不能笼统让所有故障都关闭全部输出。

SSR 可能短路失效，MCU 拉低信号不能处理功率器件已短路的情况。保留独立超温、失风保护和实体停止到加热切断执行器的路径；接触器、保险、SSR 散热与线缆按实际负载选择。现有“25A”标注不能代替热设计。[OMRON SSR 失效与保护要求](https://www.ia.omron.com/product/cautions/18/safety_precautions.html)

### 电源与尺寸

逻辑板不让约 8 A 的风机电流经过测温地回路。共地或隔离按风机控制口的参考定义设计；不能一方面断开参考地，一方面使用要求共地的单端控制信号。

Espressif 对 S3 参考设计建议 3.3 V 供电能力不低于 500 mA；整板还要留射频瞬态、外围与启动余量。温度前端的滤波/稳压与热布局同时考虑。[原理图清单](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html)、[天线与 PCB 布局](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/pcb-layout-design.html)

计算与通信部分适合做成小板；首版建议先按约 50 × 60 mm 级别评估，属于布局目标，不是已验证尺寸。端子、隔离 DC/DC、保护与外壳安装可能决定最终面积。让 220 V 功率、SSR 散热和风机大电流保持在独立功率区域，更利于小型低压控制板迭代。

当前不提供采购报价：是否保留 TC4S、测温与隔离器件、电源、端子、装配数量会显著影响整套成本，不能只用 MCU 开发板价格推算量产价。

## 6. 建议 I/O 预算

以下为功能预算，不是已验证管脚表；在原理图前用具体模组及复用表校验。未使用的控制级可以先不装元件。

| 功能 | 首版预留 | 典型 GPIO 预算 |
| --- | --- | ---: |
| TC4S RS485 | UART TX/RX、收发方向 | 3 |
| USB | D−、D+；刷机和电脑接入 | 2 |
| K 型前端 | SPI SCLK/MISO/MOSI/CS | 4 |
| SSR 命令 | 一路，经驱动级 | 1 |
| 加热许可 | 一路，结合独立门控 | 1 |
| 风机调速 | 一路，按真实接口适配 | 1 |
| 风机测速 | 一路，驱动器有输出时才接 | 1 |
| I²C 扩展 | 压差/DAC等 | 2 |
| 数字输入 | 急停反馈、独立超温、送风许可、接触器反馈 | 4 |
| 外部看门狗 | 健康心跳 | 1 |
| 本地按钮 | 启动/确认、停止状态 | 2 |
| 指示 | 状态灯、蜂鸣器 | 2 |
| **合计** | 不含可选 DRDY/FAULT 与额外调试口 | **24** |

纯网关阶段核心只是 RS485 和 USB，占 5 路；全功能预算约 24 路，再根据调试/传感器选择适量扩展。S3 模组有余量，但启动脚、USB、Flash/PSRAM 和 GPIO 输入输出限制必须先扣除，不能把所有标称 GPIO 都当普通输出。

## 7. 通信、上位机信息与实时性

推荐 Wi-Fi 为主要数据通道，USB 为电脑调试与备用接入，BLE 为配网/近距离状态或未来原生客户端的可选通道。S3 的蓝牙是 BLE，不是把现有串口直接换成经典蓝牙 SPP。

网页访问优先考虑 Wi-Fi：iPhone/iPad 上的 Chrome 不支持网页直接连接 BLE，不能假设当前网页在所有手机上都能通过蓝牙控制。原生 App 可另行实现 BLE GATT。[Google 官方兼容说明](https://support.google.com/chrome/answer/6362090?hl=en)

MCU 可提供轻量 HTTP/WebSocket 接口，或由现有 Python 适配器把设备协议映射到当前上位机 API。保留电脑/Pi 时手机可以访问其网页服务；完全脱离电脑/Pi 时，可由 S3 提供新适配的精简网页和设备 API，让手机直接接入。当前完整工作台、记录库和 AI 依赖后端，复制静态网页不能让这些功能自动在手机上完整运行；完整独立客户端需要分别迁移记录存储、文件处理和相关服务。BLE 通知和 Wi-Fi 遥测共用同一数据定义。保留当前上位机的 `pv/sv/ror/elapsed/events` 映射，并扩展能力和故障字段。

设备至少上报：

- 硬件/固件/协议版本、设备 ID、能力表、会话 ID、采样序号与 MCU 单调时间。
- 豆层温度及其有效性/断线状态、SV、RoR、运行阶段、经过时间、事件时间。
- 请求加热占空比、实际执行状态/反馈、风机指令；有测速传感器才填实测 RPM，有风量传感器才填实测风量。
- 送风许可、超温、急停、接触器反馈、故障码、复位原因和通信状态。
- 命令 request_id、接受/拒绝与原因，防重复、过期指令检查和单一控制者租约；多个客户端可以只读订阅，不能抢写控制。

SSR 占空比不是实测功率，PWM 指令不是实测风量。若要真正的功率/电流，增加相应隔离测量；若无反馈，就明确显示命令值或未知，不伪造“所有信息”。

新直采方案可先以约 4–5 Hz 温度采集/闭环、2–5 Hz 上位机更新作为调试目标；实际速率由 MAX31856 转换、工频抑制、平均次数、探头响应和控制整定决定。重复读取旧数据不算提高采样率。风机 PWM、测速捕获用硬件外设，保护动作时间另做最坏情况验证，不由 UI 刷新率决定。

S3 双核不自动保证硬实时。ESP-IDF 的 Flash 擦写等操作可能影响任务和非 IRAM 安全中断；不能仅把控制任务绑到另一核就认定无抖动。关键路径使用硬件外设、短 ISR 和内部 RAM；运行中禁用 OTA 和不可控 Flash 擦写，日志优先内存缓冲或上送。CPU 停顿时硬件 PWM 也可能继续输出，因此仍需独立的撤热路径。[Flash 并发约束](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/spi_flash/spi_flash_concurrency.html)

无线接入还需要设备配对、控制鉴权、命令确认和单一控制者管理；不能直接把当前仅监听本机、未经设备远程鉴权的控机接口开放到 Wi-Fi。AI 继续只提供分析、建议和待用户采用的方案，不直接控制输出。

## 8. 实施顺序与验收证据

1. 核对 TC4S 完整后缀/输出方式、SSR 制造商与真实接法；确认风机控制口电平、频率、线序、参考地和失效状态；核对探头绝缘形式。保留现机工作链路。
2. 用 S3 开发板 + 完整隔离 RS485 模块做只读 PV/SV 网关，接入现有 Python/桌面软件；Pi 与电脑分别验证，不能双主站争用总线。
3. 增加命令确认、断连/复位策略和设备协议；用低压测试负载验证默认关断、看门狗和联锁。随后才安排受控实机 SV 测试。
4. 新测温前端先做校验和抗干扰比对，再迁移探头；用有时间戳的测量记录核对读数、有效采样率、冷端和风机/SSR 开关干扰。
5. 建立送风许可与独立撤热链，再实现本地曲线和功率 PID；验证实际风量变化对流化与温控的影响，加入已验证的最低送风限制。
6. 测试手机/电脑断线、网络拥塞、MCU 复位、探头开路、送风故障、过温和 SSR 故障切断路径，记录最坏控制延迟和实际负载状态。
7. 通过上述接口与台架验证后再定制 PCB，验证机壳内温升、天线、供电瞬态和实机烘焙；这些结果才支撑移除树莓派和后续成本优化。

本文没有实际访问串口、驱动输出、修改现有设备连接方式或替换运行时。后续固件与板级实现应独立提交并保留真实硬件验收记录。
